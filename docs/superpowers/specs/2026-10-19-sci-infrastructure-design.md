## 用户阅读区

### 一、目标与范围

建立一个 GitHub 公有仓库 `inoceanlee/sci-infrastructure`。仓库集中维护可安装的科研基础设施 Skills。

本次重点开发 `figure-infrastructure`：帮助科研项目使用现有绘图库生成排版整洁、标注清楚、适合论文的**单张图**，并自动验收实际导出结果。

- 支持 Plotly（JavaScript）、Matplotlib 和 Seaborn（Python，复用 Matplotlib 适配）。
- 默认一张图只包含一个主绘图区；仅用户明确要求时才允许多子图。色条、图例、辅助标注不算独立子图。
- 支持 PNG 和 SVG 导出。支持 Matplotlib/Seaborn 原生 PDF。Plotly PDF 仅在现有离线环境能可靠提供时启用；不能转换时明确提示，不增加复杂转换系统。
- 沿用雷达项目单栏、双栏固定尺寸。不同格式的物理尺寸必须一致。
- 基础设施程序必须存放在 Skill 的 `scripts/` 内。Skill 文件、源码、测试一起通过 Git 管理。
- 先完成独立测试和发布，再由雷达项目接入。不得提前修改雷达项目的计算、数据或报告。

### 二、能解决哪些问题

| 常见问题 | 预期行为 |
| --- | --- |
| 数据轴范围不合适 | 默认收紧数值范围；允许固定上下界、设置最小跨度或参考范围，以免夸大微小波动 |
| 画布四周留白过多 | 固定单/双栏尺寸，在画布内压缩不必要的上、下、左、右外边距，扩大有效绘图区 |
| X 轴名称离图太远 | 分别测量绘图区、刻度数字、X 轴标题三者的位置，减少多余间距 |
| Y 轴名称离图太远 | 测量纵轴、刻度数字与旋转后的 Y 轴标题，减少多余间距 |
| 图例外置产生大片空白 | 先尝试图内安全空隙；放不下则选择贴近绘图区的图外位置，不得盖住数据 |
| 色条与绘图区相隔太远 | 测量色条、刻度和标题的边界，缩短间隙，保留原始颜色范围 |
| 峰值标签重叠 | 测量文字实际大小，重新安排位置；距离过远时添加指向原始点的引导线 |
| 图例、标题、色条相互遮挡 | 重新分配画布空间并再次检查 |
| 小提琴图、热力图格内文字不清楚 | 按各自图形类型应用布局策略，并检查字体和对比度 |
| 不同图幅排版不同 | 单栏、双栏分别排版与验收，不直接放大缩小旧图 |
| 导出后文字被裁剪 | 检查最终输出图，失败时拒绝宣称验收通过 |
| 项目之间反复修图 | 各项目复用同一 Skill 的固定版本和公开接口 |

**科学含义优先于视觉美观。** 基础设施不得修改原始数据、指标口径或既定物理参考范围。已有固定色标不能为了好看而自动收紧。整体收紧留白是调整元素间的物理距离，**不是裁剪有效数据范围、修改图幅尺寸或对导出图片进行简单白边裁切**。

自动避让并不等于任意密度都能排下。重要标注无法放入画布时，返回明确的失败结果和冲突位置；不把必需信息悄悄移入悬停提示。

### 三、图形覆盖范围

| 图形家族 | 首版直接验收的代表图 | 扩展与边界 |
| --- | --- | --- |
| 趋势与频谱 | 折线、阶梯、面积、峰值标注、误差棒/误差带 | 多系列曲线复用同一规则 |
| 分布统计 | 直方、KDE、箱线、小提琴、ECDF | 雨云图可由小提琴/箱线/散点组合；仅作为**一个主绘图区** |
| 分类与比较 | 柱状、水平柱状、堆叠柱状、点图 | 检查分类文字及数值标签 |
| 比例与组成 | 饼图、环形图、堆叠面积 | 检查扇区标签、引导线及极小份额 |
| 变量关系 | 散点、气泡、回归图、二维密度/Hexbin | 检查密集点和标签；不移动数据点 |
| 矩阵与空间 | 热力图、相关矩阵、等高线 | 格内文字与色条采用专门检查 |

首版实现常见二维家族的**共同布局与验收能力**，并为表中代表图提供测试。某个绘图库没有原生图形类型或适配测试未通过时，按库声明“不支持”，不虚构跨库一致性。Skill 应维护可查询的能力表。

### 四、论文尺寸与导出

沿用现有雷达报告两套画布：

| 预设 | 300 DPI 的 PNG | 物理画布 |
| --- | --- | --- |
| `single` 单栏 | 1004 × 709 px | 约 85 × 60 mm |
| `double` 双栏 | 2126 × 1241 px | 约 180 × 105 mm |

- PNG 像素数以表中整数为准。保存 300 DPI 元数据或验证其物理尺寸。
- SVG 使用毫米宽高与匹配的 `viewBox`，保持文本、轴单位和标注完整。
- PDF 使用同样的物理页面尺寸，优先保留矢量文字和线条。
- 对固定画布分别计算字体、边距、色条、图例与标注；不得仅把一张单栏图整体拉伸为双栏图。
- 正式导出默认一图一文件，不自动组合多子图。

## Agent 阅读区

### 六、架构取舍

已比较以下思路，并选择第三项：

| 方案 | 结果 |
| --- | --- |
| 每种图单独手工调整 | 实现快，但重复逻辑多，项目之间无法复用 |
| 自研统一跨语言绘图引擎 | 工作量大，与 Plotly/Matplotlib 的成熟能力重复 |
| **按绘图库提供适配器，按图形家族提供布局策略** | **采用**。接口与验收标准统一，绘图库保留原生绘制能力 |

职责边界：

1. **Skill 入口**：说明触发条件、支持库、安装方式、调用示例、失败处理；不得把代码复制成冗长的提示词。
2. **预设与策略**：提供单/双栏、单图约束、轴范围策略、颜色/文字布局规则。Python 与 JS 各自实现必要逻辑，不引入跨进程通讯。
3. **绘图库适配器**：取得实际字形、坐标轴、图例、色条和标注的显示尺寸；调用相应的原生绘制/导出能力。
4. **质量检查**：基于真实渲染结果检查碰撞、裁剪、偏移、尺寸、轴标题/刻度间距、图例/色条间距、四周留白及重要信息的存在性，并有限次重新排版。
5. **图形家族策略**：为不同布局对象补充约束。复用底层库的箱线、小提琴、饼图等绘制功能，不重新实现图形的统计学算法。

不得添加一个跨语言的运行时服务。共用规则可在各 Skill 脚本中保留同名常量和测试样例；无需引入庞大的统一 Schema 系统。

### 七、接口与状态契约

Python 侧提供一个高内聚入口，例如：

```python
from figure_layout import FigureExporter

result = FigureExporter().export(
    fig, path="figure.svg", kind="violin",
    preset="single", annotations=[]
)
```

JavaScript 侧提供一个异步入口，例如：

```javascript
const result = await exportScientificFigure(plotDiv, {
  kind: "line", preset: "single", format: "svg",
  annotations: []
});
```

这两个入口的参数语义一致，返回值可以遵循各语言习惯；不强制共用相同的内部类结构。

- `kind` 为可查询的图形家族或原生类型标识。不认识的标识显式报错。
- `preset` 只能取 `single` 或 `double`，默认 `single`。
- 默认 `allow_subplots=false`。如果出现多个独立主绘图区，拒绝导出并说明原因；色条不计入。
- `annotations` 是已由调用方确认的关键标注。每项至少给定正文、所指对象/位置与重要性。基于数据标注必须能追溯到原始数据位置。
- 调用方传入的数据、曲线绘制、统计量、颜色含义、轴单位及固定色标不由本 Skill 推断或更改。
- 成功状态须包含格式、预设、尺寸、可用输出及检查摘要。失败状态须包含明确原因与冲突对象，不能仅返回 `true`。
- 在 HTML 场景导出使用独立的临时图，不能改变正在浏览的原图、缩放或选择状态。Python 侧导出也不得永久改写传入 Figure 的布局状态。

**自动范围规则**：默认对未锁定的数值轴执行 `auto`，使用全量有限有效值及适当余量，减少无意义留白。开放逐轴 `range_policy`：`mode="auto"` 可设置 `min_span`（最小显示跨度，线性轴使用物理量单位，对数轴使用 log10 跨度）；`mode="fixed"` 使用显式 `bounds=[lower,upper]`，保证完整保留这些边界；`mode="reference"` 使用调用方提供的、具有科研含义的参考边界。只要声明了 `min_span`、`fixed` 或 `reference`，自动布局不得进一步收紧它。固定色标永不缩放。默认不得裁掉有效数据点；用户手动指定更窄范围时必须显式指出裁剪情况。常数列、零跨度、正负号、零附近数据、对数坐标和缺失值分别处理。**一般算法无法仅从数值大小判断波动是否具有物理意义**：调用方（例如雷达项目）可指定 `min_span` 或参考范围；图中保留真实刻度，不隐瞒纵轴截断。

**标注规则**：先尝试移动文字，再调整可用画布与图例。若文字离数据锚点过远，则添加或延长引导线；连接必须指向正确锚点。允许有意的文字覆盖色块或点标记，但禁止未经声明的文字/文字重叠、裁剪和引导线指错。优先保证重要标注完整，其次优化视觉余量。

**质量规则**：使用真正的渲染器边界盒或矢量几何判断，而不是靠字符串长度估算；遇到最小间距冲突，进行有次数上限的重排。仍未满足重要约束则返回失败。实际导出的 PNG/SVG/PDF（可用时）都要被重新读取并核对元数据或图形结构；图像快照辅助人工可读性复查，不能代替可判定的几何测试。

### 七-A、全图布局与多余留白

布局引擎区分：**固定画布（Canvas）**、**数据绘图区（Plot Area）**、**刻度文字（Ticks）**、**轴标题（Axis Titles）**、**图例（Legend）**、**色条（Colorbar）**、**标注（Annotations）**和**四侧外边距（Outer Margins）**。所有边界都来自目标尺寸下实际渲染的文字/图元矩形，并统一为 pt 物理单位。

| 关系 | 测量对象 | 自动调整 |
| --- | --- | --- |
| 画布四周 | 最外侧有效图元与画布边缘 | 收紧过大空隙，保留安全边距，不改变像素尺寸 |
| 横轴下方 | 绘图区底边、刻度框、X 轴标题 | 分别压缩两段间距，不让数字和标题碰撞 |
| 纵轴左侧 | 绘图区左边、刻度框、旋转后的 Y 轴标题 | 测量真实字体宽度和单位，不裁掉负号和标题 |
| 图例 | 图例框、曲线/置信区间/点、文字、画布 | 默认先尝试图内真实安全区域；无空间则图外紧贴安排 |
| 色条 | 绘图区、色条框、刻度和单位 | 缩短独立间距，保留固定色标和易读性 |
| 关键标注 | 标签框、数据锚点和引导线 | 避让；相距过远使用引导线，必须指向原数据 |

**执行顺序**：①应用科学数值范围、物理单位与固定色标；②按单双栏真实尺寸初次绘制；③读取渲染几何；④优先调用库的布局接口；⑤压缩多余外边距、轴标题间距、图例/色条间隙；⑥避让关键标注与放置箭头；⑦再次渲染和验收，最多重复 5 次。不能通过时保留失败诊断，禁止假装通过。

**复用图库原生能力**：Matplotlib 优先 `constrained_layout` 与真实字体测量，不能无条件与 `tight_layout` 同时启用；Plotly 优先轴 `automargin`、`title.standoff` 与 `margin.autoexpand`，但自动外扩不等于消除过大空白，仍须测量后收紧。固定画布下不能无条件使用 Matplotlib `bbox_inches="tight"` 裁切，因为它可能改变文件最终尺寸。

**接口要求**：给现有 `FigureExporter.export(...)` 和 `exportScientificFigure(...)` 增加可选 `layout_policy` / `layoutPolicy`：
- `mode="compact"`（默认）或 `"preserve"`。后者保留用户手动间距，仅检查碰撞、裁剪。
- `legend="auto"`（默认）、`"inside"`、`"outside"` 或 `"fixed"`。图内只有在不遮挡实际数据图元及关键标注时才能放；没有安全位置则退到图外且紧贴。
- `protected_areas`：预留必须保留的内容或空白；明确固定的图例和色条位置不得自动改动。
- 约束采用最终物理尺寸：轴标题与最近刻度文字至少 3 pt；图例距邻近元素至少 4 pt；色条距绘图区至少 4 pt；外框距最外侧内容至少 6 pt。优化目标是最小化**超过安全距离的额外间隙**，而不是让内容贴边。

**可验收指标**：`layout_metrics` 记录四侧 `outer_gaps_pt`、X/Y `axis_title_gaps_pt`、`legend_plot_gap_pt`、`colorbar_plot_gap_pt`、`plot_area_fraction`、`collision_count` 和 `clipping_count`。只有实际存在的布局元素才记录相应距离。可见数据空白与物理固定坐标产生的空白，不应被误判为可以裁掉的冗余。

**专项测试**：分别构造 X 轴标题额外间隙 50 pt、Y 轴 45 pt、外置图例 80 pt、色条 40 pt 和四周不均匀大边距。必须在保持实际数据、重要文字和 `1004×709 / 2126×1241` 文件尺寸不变的条件下缩短多余空隙。密集曲线图无安全图内空间时，图例必须置于图外而且靠近；不得覆盖曲线。

### 八、导出实现边界

| 环境 | PNG | SVG | PDF |
| --- | --- | --- | --- |
| Matplotlib | `savefig` | `savefig` | `savefig` 原生 |
| Seaborn | 通过 Matplotlib | 通过 Matplotlib | 通过 Matplotlib |
| Plotly.js 离线浏览器 | `toImage` | `toImage` | 仅已有离线环境证实可靠时启用 |

Plotly 路径采用：临时图渲染、几何测量、适配布局、导出、复查、释放临时节点。PDF 不应成为其他两种格式发布的阻塞条件。

Python 路径采用：原生 Figure 渲染与文字边界获取、布局调整、按固定纸张尺寸导出、复查，并恢复调用方的 Figure 状态。Seaborn 的 Figure-level FacetGrid 等在默认单图规则下不可自动放行。

不自动安装用户级依赖，不修改全局 Python/Node 环境。依赖安装限明确授权的项目隔离环境。候选成熟组件（例如 Matplotlib 标注工具）在引入前须做接口、维护和许可证核查；不把第三方源代码无审查地复制进公有仓库。

### 九、验收方案

每个 Skill 提供独立可运行的测试。自动测试使用构造数据，不依赖雷达项目或人工输入。

**功能测试**

1. 对趋势、统计分布、分类、组成、关系和矩阵图的代表类型分别执行单栏与双栏导出。
2. 逐一验证 PNG、SVG；在 Python 后端验证 PDF；Plotly PDF 仅在声明支持后测试。
3. 测试中文、英文、数学符号、长轴名、长图例、密集刻度、紧邻峰值、极小饼图份额以及稀疏热力格。
4. 单图约束：单个主绘图区通过，两个独立子图默认拒绝，显式允许后才进入受支持的多图路径；多图仍要求独立审查。
5. 数据约束：默认轴范围收紧；`auto+min_span`、`fixed`、`reference` 均按调用方设置执行。构造“100.000～100.002”的微小波动并设置 `min_span=2`，显示跨度至少 2；全零、常数、异常值、缺失和对数坐标不会静默裁剪有效数据。固定色标不变。
6. 标注约束：重要标签直接可见；碰撞解除或明确失败；引导线始终指向源数据锚点。
7. 全图留白：分别检查外边距、横/纵轴标题间距、图例与色条空隙，比较实际绘制前后的 `layout_metrics`，确认整体更紧凑且不遮挡数据。
8. Nature 审查：对 Python PDF 执行原有碰撞和字号脚本，检查其错误级别，不能用旧的审查结果冒充新图。
9. 输出约束：检查单栏/双栏尺寸，PNG 内容非空、SVG 结构和尺寸正确、PDF 页面尺寸正确。
10. 原图约束：导出前后图表交互状态及传入 Figure 关键布局不变。
11. 离线约束：Plotly 离线页面断网时可导出 PNG/SVG，未向 CDN 请求资源。
12. 能力表：每个图形类型×绘图库×导出格式均有明确 `supported`、`native_only` 或 `unsupported` 状态；不将“可绘制”误报为“已验收自动排版”。

**视觉验收**

- 使用实际渲染输出复查文字、轴标题、色条、图例和注释的遮挡与裁切。
- 重排结束仍存在不可接受碰撞时，生成诊断摘要，不把失败结果发布为成功。
- 测试不同字体可用性及回退。字体缺失不能默默造成乱码。
- 确保图形内容占用合理空间，同时避免用裁剪真实数据的方式消除留白。
- 保留检查用图片作为临时测试产物，不提交 Git。

### 十一、阶段、执行 Skills 与收尾

| 阶段 | 主要内容 | 必用 Skill |
| --- | --- | --- |
| 设计 | 核对本稿与现行需求 | Superpowers `brainstorming`、`oop-first`、`ste-zh` |
| 计划 | 明确任务顺序、接口、红绿测试、回滚 | Superpowers `writing-plans`、`project-context` |
| 实施 | 逐模块实现、测试、复查 | `executing-plans` / `test-driven-development`、`oop-first`、`auto-git-commit` |
| Python 接入 | 路径、异常、时间和日志 | `py-infrastructure`、`py-plot-academic` |
| 代码公开 | 开源组件与许可证审查、GitHub 发布 | 如需新搜 GitHub 项目，联合 `deep-research`、`pavedpath-code`、`github-research` |
| 完成 | 版本发布、验收、上下文同步 | `project-context`、`auto-git-commit` |

执行者为**本次 ChatGPT 会话**，本地电脑仅作为被授权的执行环境。每阶段直接使用可用的本地工具完成，不转交本地 Agent。

批准本稿后，单独编写实施计划供用户审阅。代码实施和 GitHub 公有发布以实施计划获批为前提。任务全部验收通过后，更新 `CONTEXT.md`，将设计稿和计划稿留在 Git 历史中，再清理仓库工作树中的已完成稿件；先合并 `main`，再删除已合并的开发分支。

**本设计的成功标准**：独立仓库能安装两个基础设施 Skills；绘图 Skill 的源码可追溯且随版本分发；代表性二维科研图完成自动排版、单/双栏导出与实际视觉验收；后续雷达项目无需重新开发通用绘图排版逻辑。
